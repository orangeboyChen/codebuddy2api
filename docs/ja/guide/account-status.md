# アカウント状態

アカウント状態では各 CodeBuddy アカウントの使用量、チェックイン、利用可能なモデルを確認します。

1. 「すべて更新」を押すか、個別アカウントの「更新」を押します。
2. プラン、使用済み / 合計、残りの割合、「リセット時刻」を確認します。
3. チェックイン状態を確認し、可能な場合は「チェックイン」または「すべてチェックイン」を押します。
4. API テストやクライアントで選ぶ前に「モデル（N）」を展開します。

各モデルには上流カタログの情報が表示されます。表示名とモデル ID（クリックでコピー）、クレジット倍率（例 `x3.33`）、説明、「エンタープライズ / 内部モデル / 無料」バッジ、さらにコンテキスト長、出力上限、画像 / ツール / 推論の対応状況です。最初の 8 件のみ表示し、「すべて表示（N）」で全件を展開します。

カタログは上流 `/v3/config` から取得し、初回取得時に認証情報へキャッシュされるため、以降のページ読み込みでは上流へ問いません。「認証情報」でモデル一覧を手動編集した場合、その編集で削除されたモデルのメタデータも破棄されます。

使用量が不明、または確認に失敗した場合は「認証情報」を確認し、「Debug」を開きます。

## 自動チェックイン

各アカウントのチェックイン行の下に「自動チェックイン」のスイッチがあります（既定はオフ）。
オンにして時刻を選ぶと、ゲートウェイがその時刻に 1 日 1 回そのアカウントをチェックインします。

時刻は**サーバーのローカルタイムゾーン**で解釈されます（アプリの他の部分と同様で、`TZ` 環境変数で指定できます）。
スケジューラはゲートウェイのプロセス内で動作するため、ゲートウェイの稼働中のみ発火します。リクエストの合間に停止する構成では、次回のポーリング時に実行されます。
すでにチェックイン済みのアカウントはスキップされ、成功した場合のみ記録されるため、失敗した場合は翌日まで待たずに再試行されます。
