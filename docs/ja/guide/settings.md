# 設定

設定ではサービスパラメータ、認証情報モデル、使用量データ、コンソールのセキュリティを管理します。

## サービス設定

| 項目                                    | 用途                                                                       |
| --------------------------------------- | -------------------------------------------------------------------------- |
| CodeBuddy API エンドポイント            | 上流 URL。既定値は `https://copilot.tencent.com`                           |
| 管理者 passkey RP ID / ドメイン         | WebAuthn の hostname。スキームとポートは含めない                           |
| 認証モード（auto/token）                | 上流認証方式                                                               |
| ネットワーク環境（internal/ioa/public） | 上流ネットワーク環境                                                       |
| ログレベル                              | `DEBUG`、`INFO`、`WARNING`、`ERROR` を選択                                 |
| API タイムアウト・最初のトークン (分)   | 最初の delta が返らないリクエストを打ち切る時間。既定値は `5`              |
| Web 検索バックエンド                    | `web_search` を実行するエンジン（1 つ選択）。後述                          |
| Web フェッチバックエンド                | ページを取得するバックエンド（複数選択、選択順に試行）。後述               |
| Hy モデルの思考深度を変換する           | 下流の思考パラメーターを上流の `reasoning_effort` へ変換する。既定値は無効 |

変更後に「保存」を押します。

API タイムアウトは、リクエスト送信から上流が最初の delta を返すまでの時間を計測します。そのため、
応答が始まらないまま待ち続ける時間に上限を設けるものです。出力が始まった後は、時間がかかる回答でも
完了まで許可されます。小数分を指定でき、`0.1`〜`1440` に制限されます。コンソールを開く前に値を
設定する場合は、環境変数 `CODEBUDDY_API_TIMEOUT_MINUTES` を使用してください。

Hy モデル（`hy3` など）は `reasoning_effort` の `no_think` / `low` / `high` のみを受け付けますが、
下流クライアントはこの語彙を使いません。Claude Code は Anthropic の `thinking` を、Codex は
Responses の `reasoning.effort` を送信します。この設定を有効にすると、両者を Hy の語彙へ変換します。

| 下流の値                                     | 変換結果   |
| -------------------------------------------- | ---------- |
| `thinking.type: disabled`、`minimal`、`none` | `no_think` |
| `budget_tokens` ≤ 8K、`low`、`medium`        | `low`      |
| `budget_tokens` > 8K、`high`、`xhigh`、`max` | `high`     |

モデル名が `hy` で始まるものはすべて Hy モデルとして扱います（大文字小文字を無視）。そのため `hy3` や
`hy3-ioa` は一致し、将来の `hy4` もコード変更なしで対象になります。`hunyuan-*` は別の接頭辞・別の
製品系列のため一致しません。変換できた場合、元の `thinking` フィールドは削除されます。同じ内容を
2 つの語彙で二重に指定することを避け、この変換が対象とする上流での拒否も防ぐためです。既定値は
無効で、リクエストはそのまま転送されます。コンソールを開く前に環境変数
`CODEBUDDY_HY_THOUGHT_DEPTH_ENABLED` で設定できます（`true` / `false`）。

## サーバーツール

Anthropic のクライアントは検索とフェッチをサーバーサイドツール
（`web_search_20260209`、`web_fetch_20250910`）として宣言し、Codex は
`web_search_preview` を宣言します。CodeBuddy には同等の機能がないため、クライアントが
これらを宣言した場合、プロキシは通常の関数ツールに差し替えて自ら実行し、結果を tool
メッセージとして追記します。モデルは通常どおり応答し、クライアントはローカルで処理された
ことを認識しません。

### Web 検索バックエンド

`web_search` は選択した 1 つのエンジンが実行します。設定の有無にかかわらずすべての
エンジンが表示され、選択すると必要な入力欄が現れます。

| バックエンド | 設定項目                                         | 備考                                                        |
| ------------ | ------------------------------------------------ | ----------------------------------------------------------- |
| `codebuddy`  | なし                                             | CodeBuddy の `/agenttool/v1/search`。保存済み資格情報が必要 |
| `searxng`    | インスタンスのアドレス（ポートを含む）、API キー | 自分のインスタンス。既定値。キーは任意                      |
| `duckduckgo` | 地域                                             | 資格情報は不要。キュレーションされたインスタント回答を返す  |
| `brave`      | API キー                                         | Brave Search。独立したインデックス                          |
| `tavily`     | API キー                                         | スニペットではなくページ本文を返す                          |
| `serper`     | API キー                                         | Serper 経由で Google の結果を返す                           |
| `bing`       | API キー                                         | Bing Web Search                                             |
| `exa`        | API キー                                         | 意味的に一致させるセマンティック検索                        |

実行できないエンジン（キーが未入力、SearXNG のアドレスなし）はバックエンドなしとして
解決され、ツールは失敗させるのではなくリクエストから削除されます。既定値が `searxng`
であるのはこのためです。新規デプロイにはアドレスがないため、入力されるまで何も宣言しません。
唯一の例外は `codebuddy` で、固有の設定が不要なため選択されれば常に提供され、資格情報がない
場合はツールを削除せず検索失敗として報告します。

一覧の最後の**オフ**は無効化のための選択肢です。これを選ぶ（または
`CODEBUDDY_WEB_SEARCH_BACKEND=none` を設定する）とゲートウェイは `web_search` を実行せず、
クライアントが宣言したこのツールはリクエストから削除されます。この一覧が存在する以前に
`none` を保存したデプロイでも、アップグレード後も同じ意味のままです。

### Web フェッチバックエンド

複数のバックエンドを選択でき、選択した順に試行され、最初に成功した結果が採用されます。
直接取得を拒否するページもあれば、ブラウザーを使う取得は直接取得よりはるかに遅いなど、
失敗の仕方が異なるため、複数選ぶ意味があります。

| バックエンド    | 設定項目           | 備考                                                                    |
| --------------- | ------------------ | ----------------------------------------------------------------------- |
| `codebuddy`     | なし               | CodeBuddy の `/agenttool/v1/webfetch`。失敗時は直接取得にフォールバック |
| `codebuddy2api` | なし               | このサーバーが直接取得し、HTML をテキストに変換する。既定値             |
| `browserable`   | アドレス、API キー | Browserable のデプロイで実際のブラウザーを操作する。キーは任意          |
| `jina`          | API キー           | Jina Reader がページを Markdown で返す。キーは任意                      |

何も選択しないことが、このツールを無効にする方法です。`web_fetch` は既定でローカル実行される
ようになったため、以前 `passthrough` のままにしていたデプロイはアップグレード後に自らページを
取得し始めます。選択を空にすれば元に戻ります。

`codebuddy` を選ぶ理由は、それが CodeBuddy CLI 自身が呼び出すエンドポイントだからです。
追加のデプロイは不要で、ゲートウェイに保存済みの資格情報で認証できます。

`codebuddy2api` のフェッチバックエンドは、URL をモデル由来の信頼できない入力として扱います。
接続前にプライベートアドレスとループバックアドレスを拒否し、リダイレクトの各段で再検証する
ため、公開 URL がデプロイ自身のネットワークへリダイレクトされることはありません。

どちらの選択も、コンソールを開く前に `CODEBUDDY_WEB_SEARCH_BACKEND`、
`CODEBUDDY_WEB_FETCH_BACKEND`（後者はカンマ区切りのリスト）で設定できます。また各
バックエンドの設定にも対応する環境変数があります（`CODEBUDDY_SEARXNG_URL`、
`CODEBUDDY_BRAVE_API_KEY`、`CODEBUDDY_BROWSERABLE_URL` など）。SearXNG はコンソールの
欄が空の場合、`SEARXNG_URL` と `SEARXNG_API_KEY` も引き続き参照します。

## モデルと使用量

- 「認証情報モデル」ではモデル一覧を編集するか、「更新」を押して再取得します。
- 「使用量統計キャッシュ」の「使用量統計キャッシュを消去」はすべての使用量記録を完全に削除します。

## コンソールのセキュリティ

「コンソールのセキュリティ」で管理者ユーザー名、パスワード、確認用パスワードを設定し、「保存」を押します。認証を無効にするとコンソールへ直接アクセスできます。
